# Issue Tracker: Vikunja через veans

Задачи и спецификации репозитория хранятся в проекте локальной Vikunja. Файл `.veans.yml` задаёт project, Kanban view, buckets и bot user.

## Базовые правила

- Выполняй `veans` из корня репозитория.
- Перед первым tracker workflow выполни `veans prime` и следуй его правилам HTML.
- Название задачи — plain text. Description и comments — HTML, не Markdown.
- Label передаётся в CLI без `veans:`; клиент добавляет prefix сам.
- Не создавай параллельные задачи в `.scratch/`.
- Pull request не является request surface этого tracker.

## Чтение и изменение

```bash
veans list
veans list --ready
veans show PROJ-12
veans api GET /tasks/12/comments | jq '.items'
veans update PROJ-12 --comment '<p>Комментарий</p>'
```

`veans show` не возвращает comments. Для полного контекста всегда читай задачу и `/tasks/<numeric-id>/comments`.

## to-spec

Создай одну задачу в `todo` с label `ready-for-agent`. Перенеси смысл шаблона skill в семантический HTML: заголовки — `<h2>`, абзацы — `<p>`, списки — `<ul>` или `<ol>`, код — TipTap code block из `veans prime`.

```bash
veans create 'Короткое название спецификации' \
  --status todo \
  --label ready-for-agent \
  --description '<h2>Проблема</h2><p>...</p><h2>Критерии готовности</h2><ul><li><p>...</p></li></ul>'
```

## to-tickets

Создавай отдельную задачу на каждый implementation slice. Epic/spec указывай через `--parent`, прямые зависимости — через повторяемый `--blocked-by`. Каждая готовая задача получает `ready-for-agent`.

```bash
veans create 'Первый slice' --parent PROJ-10 --label ready-for-agent --description '<p>...</p>'
veans create 'Второй slice' --parent PROJ-10 --blocked-by PROJ-11 --label ready-for-agent --description '<p>...</p>'
```

Создавай blockers раньше зависимых задач. После публикации проверь `veans list --ready`.

## triage

Фактические labels перечислены в `docs/agents/triage-labels.md`. При смене роли сначала сними прежнюю state-role, затем добавь новую. Triage-комментарий должен содержать HTML-disclaimer:

```html
<blockquote><p><em>This was generated by AI during triage.</em></p></blockquote>
```

Пример:

```bash
veans update PROJ-12 \
  --label-add bug \
  --label-remove needs-triage \
  --label-add ready-for-agent \
  --comment '<blockquote><p><em>This was generated by AI during triage.</em></p></blockquote><p>...</p>'
```

### Закрытие wontfix

Не используй `veans update --status scrapped` с `veans 2.4.0`: Vikunja снимает `done` после переноса из Done в Scrapped. Для claimed-задач обычный PATCH завершения также может вернуть `422` из-за `subscription.entity`.

Добавь `wontfix`, сними прежнюю state-role, оставь пояснение и перемести задачу прямо в настроенный Done bucket:

```bash
project_id="$(awk '$1 == "project_id:" {print $2}' .veans.yml)"
view_id="$(awk '$1 == "view_id:" {print $2}' .veans.yml)"
done_bucket_id="$(awk '$1 == "done:" {print $2}' .veans.yml)"
task_id="$(veans show PROJ-12 | jq -er '.id')"
veans update PROJ-12 --label-remove needs-triage --label-add wontfix \
  --comment '<blockquote><p><em>This was generated by AI during triage.</em></p></blockquote><p>Причина закрытия.</p>'
veans api PUT "/projects/$project_id/views/$view_id/buckets/$done_bucket_id/tasks" \
  --data "{\"task_id\":$task_id}"
```

Label `veans:wontfix` отличает отказ от выполненной задачи, а Done корректно разблокирует зависимые задачи.

## wayfinder

- Map — parent task с Notes, Decisions-so-far и Fog в description/comments.
- Child — отдельная задача с `--parent <map-id>`.
- Blocking — relation `--blocked-by`; готовый frontier выдаёт `veans list --ready`.
- Claim — `veans claim <id>` до начала работы.
- Resolve — добавь answer/context comment, переведи в `in-review`; человек принимает работу переносом в Done.

```bash
veans claim PROJ-12
veans update PROJ-12 --status in-review --comment '<h2>Ответ</h2><p>...</p>'
```

## Когда skill говорит publish или fetch

- `publish to the issue tracker`: создай или обнови задачу через `veans`, затем верни её identifier.
- `fetch the relevant ticket`: выполни `veans show`, прочитай comments через API, затем при необходимости прочитай parent и blockers из `related_tasks`.
