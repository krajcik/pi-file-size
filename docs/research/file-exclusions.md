# Research: default file-exclusion policy

## Scope and decision

This document recommends which **text** files should be ineligible for a non-blocking size nudge after an observed Pi `edit` or `write`. Eligibility is decided before applying the product defaults: more than 1,000 physical lines, or net growth of at least 150 physical lines in an already-oversized file. The objective is to suppress noise from mechanically large artifacts without suppressing hand-written code, documentation, configuration, schemas, or data merely because of their language.

**Recommended default:** use a layered classifier, not one extension list. Give an explicit user inclusion the highest precedence; then honor explicit repository classification; then use high-confidence exact names and paths; then inspect a small header/trailer window for generator and source-map signatures; otherwise keep the text file eligible. Treat ambiguous categories as eligible.

GitHub Linguist is useful precedent, but not a policy to copy wholesale. Linguist excludes generated and vendored files, while also excluding documentation and languages classified as prose or data for the separate purpose of repository language statistics; this product explicitly needs to retain hand-written docs and declarative files. ([Linguist: how it works](https://github.com/github-linguist/linguist/blob/main/docs/how-linguist-works.md), [Linguist overrides](https://github.com/github-linguist/linguist/blob/main/docs/overrides.md))

## Findings from primary sources

### Generated files: markers and paths are ecosystem-specific

| Ecosystem/toolchain | Primary-source finding | Default consequence |
|---|---|---|
| Go | The Go tool specifies `^// Code generated .* DO NOT EDIT\.$` and requires it before the first non-comment, non-blank text. ([`go generate`](https://pkg.go.dev/cmd/go#hdr-Generate_Go_files_by_processing_source)) | Recognize the exact Go marker; do not infer generation from `.go`. |
| Java/JVM | Java's `javax.annotation.processing.Generated` identifies generated source, records generator names, and has source-only retention. ([Java SE API](https://docs.oracle.com/en/java/javase/21/docs/api/java.compiler/javax/annotation/processing/Generated.html)) | Recognize `@Generated(...)` near the top when it is the Java annotation; generated Java may have no durable path convention. |
| .NET | .NET's `GeneratedCodeAttribute` identifies code generated by a tool and carries tool name/version. ([.NET API](https://learn.microsoft.com/en-us/dotnet/api/system.codedom.compiler.generatedcodeattribute)) Linguist additionally recognizes `.designer.cs`, `.designer.vb`, and `.feature.cs` as generated conventions. ([Linguist generated classifier](https://github.com/github-linguist/linguist/blob/main/lib/linguist/generated.rb)) | Recognize the attribute/header and those narrow suffixes; do not exclude all partial classes or all `.cs`/`.vb`. |
| Rust/Cargo | Cargo build scripts place generated artifacts in `OUT_DIR`, and Cargo places build output in the target directory; both locations are configurable. ([Cargo build scripts](https://doc.rust-lang.org/cargo/reference/build-scripts.html#outputs-of-the-build-script), [Cargo build cache](https://doc.rust-lang.org/cargo/reference/build-cache.html)) | Exclude known Cargo output paths; there is no language-wide checked-in Rust marker to assume. |
| JavaScript/TypeScript | TypeScript's `outDir` controls output location and `sourceMap` emits `.js.map`; both are options rather than fixed project paths. ([TypeScript `outDir`](https://www.typescriptlang.org/tsconfig/outDir.html), [TypeScript `sourceMap`](https://www.typescriptlang.org/tsconfig/sourceMap.html)) Relay writes compiler artifacts to `__generated__` directories. ([Relay fragments](https://relay.dev/docs/guided-tour/rendering/fragments/)) | Exclude source maps and `__generated__`; use markers/output paths for emitted JS/TS rather than excluding `.js`, `.ts`, or `.d.ts`. |
| Protocol Buffers/gRPC and other generators | Protobuf maintains separate generated-code conventions for C++, C#, Dart, Go, Java, Kotlin, Objective-C, PHP, Python, Ruby, and Rust. ([Protobuf generated-code reference](https://protobuf.dev/reference/)) Linguist's first-party classifier recognizes the emitted headers/suffixes for Protobuf/gRPC, Thrift, Cython, Dart `source_gen`, jOOQ, JFlex, roxygen2, and others rather than relying on one universal marker. ([Linguist generated classifier](https://github.com/github-linguist/linguist/blob/main/lib/linguist/generated.rb)) | Recognize a conservative common marker plus narrow well-known codegen suffixes. Keep schema inputs (`.proto`, OpenAPI, GraphQL, etc.) eligible unless they themselves carry a generated marker. |

A literally complete static list is not possible: output locations are configurable in mainstream tools, language annotations can disappear after source processing, and generators use many distinct signatures. The continuing tool-specific checks in Linguist and its explicit `linguist-generated` / `linguist-vendored` overrides are practical evidence that classification requires both evolving heuristics and repository knowledge. ([TypeScript `outDir`](https://www.typescriptlang.org/tsconfig/outDir.html), [Cargo build cache](https://doc.rust-lang.org/cargo/reference/build-cache.html), [Java `Generated`](https://docs.oracle.com/en/java/javase/21/docs/api/java.compiler/javax/annotation/processing/Generated.html), [Linguist generated classifier](https://github.com/github-linguist/linguist/blob/main/lib/linguist/generated.rb), [Linguist overrides](https://github.com/github-linguist/linguist/blob/main/docs/overrides.md))

### Lockfiles

Lockfiles are machine-maintained resolution records even when they should be committed. For example, npm says `package-lock.json` is automatically generated and intended for source control; Cargo distinguishes editable `Cargo.toml` from generated `Cargo.lock`; Go describes `go.sum` as cryptographic checksums maintained by the `go` command; Composer recommends committing `composer.lock`; and uv says `uv.lock` should not be edited by hand and should be committed. ([npm](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json), [Cargo](https://doc.rust-lang.org/cargo/guide/cargo-toml-vs-cargo-lock.html), [Go modules](https://go.dev/ref/mod#go-sum-files), [Composer](https://getcomposer.org/doc/01-basic-usage.md#commit-your-composer-lock-file-to-version-control), [uv](https://docs.astral.sh/uv/concepts/projects/layout/#the-lockfile))

**Decision:** exclude known lockfile basenames by default. Do **not** use `*.lock`: that broad glob can classify an unrelated application file solely by suffix. Tool-owned documentation also confirms the configurable or standard names for Yarn, pnpm, Bun, Terraform, Gradle, and NuGet locks. ([Yarn](https://yarnpkg.com/configuration/yarnrc#lockfileFilename), [pnpm](https://pnpm.io/settings#lockfile), [Bun](https://bun.sh/docs/install/lockfile), [Terraform](https://developer.hashicorp.com/terraform/language/files/dependency-lock), [Gradle](https://docs.gradle.org/current/userguide/dependency_locking.html), [NuGet](https://learn.microsoft.com/en-us/nuget/consume-packages/package-references-in-project-files#locking-dependencies))

### Vendored dependencies

Go's `go mod vendor` copies dependency packages into `vendor` and writes `vendor/modules.txt`; `cargo vendor` vendors dependencies into a requested directory; and Node installs packages into `node_modules`. ([Go vendoring](https://go.dev/ref/mod#vendoring), [`cargo vendor`](https://doc.rust-lang.org/cargo/commands/cargo-vendor.html), [npm folders](https://docs.npmjs.com/cli/v11/configuring-npm/folders#node-modules)) Linguist's maintained vendor rules cover `node_modules`, Bower components, `vendor`, `third_party`, `external`, `deps`, CocoaPods, Carthage build products, and tool-specific dependency trees. ([Linguist `vendor.yml`](https://github.com/github-linguist/linguist/blob/main/lib/linguist/vendor.yml))

**Decision:** exclude conventional vendored trees. This is intentionally path-based because their contents can be ordinary, readable source indistinguishable from first-party source. Broad names such as `deps`, `external`, and `vendor` need force-include support because repositories can use those names for first-party code.

### Minified, bundled, and source-map output

TypeScript source maps are emitted artifacts. The Source Map specification defines the map's JSON structure and the `sourceMappingURL` link from generated code. ([TypeScript `sourceMap`](https://www.typescriptlang.org/tsconfig/sourceMap.html), [ECMA-426 Source Map specification](https://tc39.es/ecma426/)) Linguist treats JS/CSS with a source-map trailer as generated, recognizes `.js.map`/`.css.map` or map JSON signatures, and uses a JS/CSS average-line-length heuristic for minification; its vendor rules also recognize `*.min.js` and `*.min.css`. ([Linguist generated classifier](https://github.com/github-linguist/linguist/blob/main/lib/linguist/generated.rb), [Linguist `vendor.yml`](https://github.com/github-linguist/linguist/blob/main/lib/linguist/vendor.yml))

**Decision:** exclude narrow minified/bundle/map names and source-map signatures. Do not apply minification heuristics to arbitrary JSON, prose, or code: long lines can be hand-written, and a one-line minified artifact cannot cross a 1,000-physical-line threshold anyway.

### Snapshots, golden files, and fixtures

Jest creates `.snap` reference artifacts under `__snapshots__`; it also says snapshots should be committed and reviewed as part of tests. ([Jest snapshot testing](https://jestjs.io/docs/snapshot-testing)) Jest permits a custom `snapshotResolver`, so even its snapshot path convention is overridable. ([Jest configuration](https://jestjs.io/docs/configuration#snapshotresolver-string)) Rust's Insta likewise writes pending and accepted snapshot files through its snapshot workflow. ([Insta quickstart](https://insta.rs/docs/quickstart/))

**Decision:** exclude unmistakable snapshot/golden outputs (`__snapshots__`, `.snap`, and explicit `golden` naming) because regeneration can create large mechanical growth. Do not exclude generic `testdata`, `fixtures`, `expected`, or every file used as a test oracle: Go reserves `testdata` as an ignored-by-build directory for auxiliary test data, not as a generated-output declaration. ([Go package lists](https://pkg.go.dev/cmd/go#hdr-Package_lists_and_patterns)) A repository with hand-curated `.snap` or `golden` files must be able to force-include them; review value does not make their contents hand-authored. ([Jest snapshot testing](https://jestjs.io/docs/snapshot-testing))

### Build, distribution, and coverage output

Standard tools use recognizable but configurable output locations: Python packaging writes distribution archives to `dist`; Maven's standard layout uses `target`; Cargo uses its target directory; Jest's `coverageDirectory` defaults to `coverage` but is configurable; and .NET's base output/intermediate paths default under `bin`/`obj` but can be changed. ([Python Packaging User Guide](https://packaging.python.org/en/latest/tutorials/packaging-projects/#generating-distribution-archives), [Maven layout](https://maven.apache.org/guides/introduction/introduction-to-the-standard-directory-layout.html), [Cargo build cache](https://doc.rust-lang.org/cargo/reference/build-cache.html), [Jest configuration](https://jestjs.io/docs/configuration#coveragedirectory-string), [.NET SDK properties](https://learn.microsoft.com/en-us/dotnet/core/project-sdk/msbuild-props#baseoutputpath))

**Decision:** exclude conventional output directories, with overrides. Do not exclude every `bin` directory: many repositories keep hand-written command scripts there. A changed/custom output directory cannot be found reliably without repository configuration, which is another reason the defaults cannot be complete.

### Schemas, API descriptions, and codegen output

An OpenAPI document is a machine-readable description of an HTTP API; it is an input/contract, not necessarily generator output. ([OpenAPI Specification](https://spec.openapis.org/oas/latest.html)) TypeScript declaration files can be authored to describe an existing JavaScript library, so `.d.ts` does not mean generated. ([TypeScript declaration-file introduction](https://www.typescriptlang.org/docs/handbook/declaration-files/introduction.html)) Rails says its schema dump is generated and strongly recommends checking it into source control. ([Rails schema dumping](https://guides.rubyonrails.org/active_record_migrations.html#schema-dumping-and-you))

**Decision:** exclude emitted clients/models only when a marker, explicit generated path, repository declaration, or narrow tool suffix identifies them. Exclude Rails `db/schema.rb` and `db/structure.sql` as known schema dumps. Keep source schemas and API contracts—including `.proto`, OpenAPI JSON/YAML, GraphQL schema files, JSON Schema, SQL DDL, and hand-written `.d.ts`—eligible by default.

### Migrations and declarative data must remain eligible

Django describes migrations as a version-control-friendly history that is designed to be committed and distributed with the codebase, and supports hand-written data migrations. ([Django migrations](https://docs.djangoproject.com/en/5.2/topics/migrations/)) Rails migrations are a Ruby DSL for database changes and may be created by a generator or written by hand. ([Rails migrations](https://guides.rubyonrails.org/active_record_migrations.html)) Therefore a path named `migrations` is not sufficient evidence of mechanically generated content.

Kubernetes declarative configuration records desired object state in files, and Terraform configuration describes infrastructure in its declarative language. ([Kubernetes declarative management](https://kubernetes.io/docs/tasks/manage-kubernetes-objects/declarative-config/), [Terraform language](https://developer.hashicorp.com/terraform/language)) These are exactly the kinds of hand-maintained files for which excessive physical growth may be worth a nudge.

**Decision:** do **not** exclude migrations, SQL, JSON, YAML, TOML, XML, CSV, infrastructure-as-code, manifests, or configuration by extension or generic directory name. A specific file can still be excluded by a stronger signal such as a generator marker, known lockfile basename, generated schema-dump name, explicit output path, or user override.

## Recommended layered default policy

Apply these layers in order; the first decisive result wins.

1. **Explicit force-include / force-exclude.** A force-include must override every built-in path, name, marker, and heuristic. A force-exclude suppresses the nudge for any matching text file.
2. **Repository-owned declarations.** If supported, consume explicit `linguist-generated` and `linguist-vendored` values (including negative values) from `.gitattributes`; Git defines attribute states including Set, Unset, value, and Unspecified, and Linguist documents these specific attributes. ([Git attributes](https://git-scm.com/docs/gitattributes), [Linguist overrides](https://github.com/github-linguist/linguist/blob/main/docs/overrides.md)) Do not import Linguist's `documentation` or `detectable` decisions.
3. **Exact basenames and high-confidence paths.** Apply the default tables below to normalized repository-relative paths.
4. **Content signatures.** For text not already decided, inspect only the first 40 lines (plus the final two lines for source-map links). Use exact/tool-specific signatures or a conservative “generated” **and** “do not edit/modify” pairing. Linguist similarly bounds many marker checks to the first few lines, checks Go within the first 40, and checks source-map references at the end. ([Linguist generated classifier](https://github.com/github-linguist/linguist/blob/main/lib/linguist/generated.rb))
5. **Eligible by default.** Unknown or ambiguous text stays eligible. Apply the 1,000-line / +150-growth nudge logic only now.

A marker should not override an explicit force-include. Do not scan the entire file for generic phrases: documentation and fixtures may quote a generated-file header.

## Concrete recommended defaults

Pattern notation below is policy notation, not a mandate for a particular glob library: `**` means any depth, `/` is the normalized separator, and basename matches apply at any depth.

### Exact/basename exclusions

**Lock and resolver artifacts** (exact basename unless a path is shown):

```text
package-lock.json        npm-shrinkwrap.json       yarn.lock
pnpm-lock.yaml           bun.lock                  bun.lockb
deno.lock                Cargo.lock                go.sum
composer.lock            Gemfile.lock              Pipfile.lock
poetry.lock              pdm.lock                  uv.lock
Package.resolved         packages.lock.json        gradle.lockfile
flake.lock               MODULE.bazel.lock         .terraform.lock.hcl
Manifest.toml            JuliaManifest.toml        pixi.lock
**/gradle/dependency-locks/*.lockfile
```

The broad compatibility set above tracks names recognized by tool documentation and Linguist's maintained generated classifier; it should be versioned and testable rather than expanded to `*.lock`. ([Linguist generated classifier](https://github.com/github-linguist/linguist/blob/main/lib/linguist/generated.rb))

**Narrow generated/snapshot/map names:**

```text
*.min.js                 *.min.css                 *-min.js
*-min.css                *.bundle.js              *.bundle.css
*.chunk.js               *.chunk.css              *.js.map
*.css.map                *.snap                    *.snap.new
*.designer.cs            *.designer.vb            *.feature.cs
*.pb.go                  *_grpc.pb.go              *_pb2.py
*_pb2_grpc.py            *.pb.cc                   *.pb.h
*.grpc.pb.cc             *.grpc.pb.h               *.pb.dart
*.generated.*            *.g.cs                    *.g.i.cs
db/schema.rb             db/structure.sql
```

`*.generated.*` is intentionally narrower than `*.gen.*`; projects that use “generated” as a human-authored module name can force-include it. Protobuf variants and generated framework names continue to require marker/path detection because no suffix table covers all generators. ([Protobuf generated-code reference](https://protobuf.dev/reference/), [Linguist generated classifier](https://github.com/github-linguist/linguist/blob/main/lib/linguist/generated.rb))

### Directory exclusions

```text
# Vendored/dependency trees
**/node_modules/**        **/bower_components/**    **/vendor/**
**/vendors/**             **/third_party/**         **/third-party/**
**/3rdparty/**            **/external/**            **/externals/**
**/deps/**                **/Pods/**                **/Carthage/Build/**
**/.yarn/cache/**         **/.yarn/unplugged/**

# Generated/codegen trees
**/__generated__/**       **/generated-sources/**
**/build/generated/**     **/target/generated-sources/**
**/.openapi-generator/**

# Snapshots/goldens (not generic fixture/testdata paths)
**/__snapshots__/**       **/golden/**               **/goldens/**

# Build/distribution/coverage output
**/dist/**                **/build/**                **/out/**
**/target/**              **/obj/**                  **/coverage/**
**/htmlcov/**             **/lcov-report/**          **/.nyc_output/**
**/.next/**               **/.nuxt/**                **/.svelte-kit/**
**/_build/**              **/_site/**                **/bazel-out/**
```

These intentionally favor quiet defaults for conventional mechanical-output paths, but `build`, `out`, `target`, `deps`, `external`, and `golden` have meaningful false-positive risk. They are defensible only with a highest-precedence force-include and clear classification diagnostics. Linguist's own vendor list is broader and evolving, reinforcing the need to keep this set reviewable rather than silently inheriting it. ([Linguist `vendor.yml`](https://github.com/github-linguist/linguist/blob/main/lib/linguist/vendor.yml), [Linguist overrides](https://github.com/github-linguist/linguist/blob/main/docs/overrides.md))

### Content signatures

Exclude when one of these appears in the bounded header window:

- the exact Go marker `^// Code generated .* DO NOT EDIT\.$`; ([Go tool](https://pkg.go.dev/cmd/go#hdr-Generate_Go_files_by_processing_source))
- a comment containing a case-insensitive generated phrase (`code generated`, `generated code`, `auto-generated`, `autogenerated`, or `this file is generated`) **and**, within the same or adjacent comment line, `do not edit`, `do not modify`, or `not intended for manual editing`;
- recognized tool headers such as `Generated by the protocol buffer compiler`, `Generated by the gRPC`, `Autogenerated by Thrift Compiler`, `Generated by Cython`, `Generated by jOOQ`, `generated by JFlex`, or `Generated by roxygen2`; these are implemented as bounded, extension-aware checks by Linguist. ([Linguist generated classifier](https://github.com/github-linguist/linguist/blob/main/lib/linguist/generated.rb))
- Java/.NET generated annotations when syntactically used as annotations/attributes, not merely mentioned in prose. ([Java SE API](https://docs.oracle.com/en/java/javase/21/docs/api/java.compiler/javax/annotation/processing/Generated.html), [.NET API](https://learn.microsoft.com/en-us/dotnet/api/system.codedom.compiler.generatedcodeattribute))
- for JS/CSS only, a final-line `sourceMappingURL` directive; for `.map`, a valid source-map top-level JSON signature rather than extension alone for arbitrary `*.map`. ([ECMA-426](https://tc39.es/ecma426/), [Linguist generated classifier](https://github.com/github-linguist/linguist/blob/main/lib/linguist/generated.rb))

Avoid a bare `@generated` default unless it is tied to a known tool syntax/signature; it is too easy to quote in documentation.

## Categories that should **not** be excluded by default

- Documentation and prose (`README`, `docs/**`, Markdown, AsciiDoc, reStructuredText).
- Ordinary source code, including already-large legacy files; only the product's first-crossing/significant-growth rules decide whether to nudge.
- Migrations and migration directories. ([Django](https://docs.djangoproject.com/en/5.2/topics/migrations/), [Rails](https://guides.rubyonrails.org/active_record_migrations.html))
- Source schemas and API contracts: `.proto`, OpenAPI, GraphQL schema, JSON Schema, SQL DDL, and hand-authored `.d.ts`. ([OpenAPI Specification](https://spec.openapis.org/oas/latest.html), [TypeScript declaration files](https://www.typescriptlang.org/docs/handbook/declaration-files/introduction.html))
- Declarative configuration/data by extension: JSON, YAML, TOML, XML, SQL, CSV, Kubernetes manifests, Terraform, CI configuration, and package manifests. ([Kubernetes](https://kubernetes.io/docs/tasks/manage-kubernetes-objects/declarative-config/), [Terraform](https://developer.hashicorp.com/terraform/language))
- Generic `fixtures/**`, `testdata/**`, `expected/**`, examples, and sample applications. `testdata` has a Go build meaning but no generated-content guarantee. ([Go package lists](https://pkg.go.dev/cmd/go#hdr-Package_lists_and_patterns))
- `bin/**` and `scripts/**`, which must not be conflated with .NET binary output solely by name; use a tool-specific output path or override.
- All `.d.ts`, `.lock`, `.map`, `.json`, or `.sql` files by extension alone.
- Files merely ignored by Git. Git's ignore/exclude mechanism controls untracked-file visibility, while attributes provide per-path metadata; ignore status is not a generated/vendored assertion. ([Git ignore](https://git-scm.com/docs/gitignore), [Git attributes](https://git-scm.com/docs/gitattributes))

## Override and explainability requirements

A public extension needs repository-local, versionable controls for:

- ordered `forceInclude` and `forceExclude` path patterns, with force-include winning;
- adding generated markers and generated/vendored/output paths for local generators;
- disabling individual built-in patterns without replacing the whole default set;
- deterministic path normalization and documented case behavior;
- an optional “why was this file ineligible?” diagnostic that reports the winning rule (for example, `lockfile: Cargo.lock`, `path: **/dist/**`, or `marker: Go generated header`);
- no requirement to edit a generated artifact merely to annotate it; repository-level classification must suffice.

This mirrors the practical need exposed by Linguist's positive and negative `.gitattributes` overrides, while keeping this product's policy independent from Linguist's documentation/data exclusions. ([Linguist overrides](https://github.com/github-linguist/linguist/blob/main/docs/overrides.md))

## False-positive and false-negative risks

| Risk | Examples | Mitigation |
|---|---|---|
| False positive: conventional path contains first-party work | `build/` scripts, `deps/` internal modules, a hand-curated `golden/`, source under `vendor/` | Force-include precedence; allow disabling a built-in; report the matching rule. |
| False positive: marker quoted rather than active | Documentation or parser tests containing `DO NOT EDIT` | Header-only scan; require paired phrases; extension/tool-aware signatures; annotation syntax checks. |
| False positive: suffix has another meaning | geographic `*.map`, hand-authored `.d.ts`, application `*.lock` | Do not use broad extension-only rules; validate source-map content; exact lock names only. |
| False negative: custom generator/output path | TypeScript custom `outDir`, custom Jest snapshot resolver, custom Cargo target dir | Repository overrides; optionally honor explicit `.gitattributes`; do not claim completeness. ([TypeScript](https://www.typescriptlang.org/tsconfig/outDir.html), [Jest](https://jestjs.io/docs/configuration#snapshotresolver-string), [Cargo](https://doc.rust-lang.org/cargo/reference/build-cache.html)) |
| False negative: generated file has no marker | checked-in compiler output renamed into a source tree | Explicit path classification and narrow tool suffixes; retain conservative eligible fallback. |
| Staleness | new lockfiles, frameworks, and generator signatures | Version and test the defaults; review upstream tool docs and Linguist changes periodically rather than fetching mutable policy at runtime. ([Linguist generated classifier](https://github.com/github-linguist/linguist/blob/main/lib/linguist/generated.rb), [Linguist vendor rules](https://github.com/github-linguist/linguist/blob/main/lib/linguist/vendor.yml)) |

The fallback should prefer an occasional nudge (false negative) over silently suppressing size guidance for hand-written code/docs (false positive), because nudges are non-blocking and explicit exclusions remain available.

## Unresolved validation questions

1. On a representative corpus, what precision/recall results do the broad directory defaults (`build`, `out`, `target`, `deps`, `external`, `golden`) produce? Consider moving low-precision entries to opt-in presets.
2. Should `.gitattributes` support be part of v1, and if so, will nested attribute files, negative attributes, and Git's pattern semantics be implemented exactly or documented as a subset? ([Git attributes](https://git-scm.com/docs/gitattributes))
3. What is the exact configuration schema and precedence between global settings, repository settings, `.gitattributes`, force-includes, and force-excludes?
4. Should generator-marker inspection be capped by lines, bytes, or both, and how should BOMs/encodings be handled while preserving the product's definition of text?
5. Should `*.bundle.js` / `*.chunk.js` require a source-map or minification signal to reduce false positives, given that physical-line counting already makes one-line minified files harmless?
6. Are checked-in snapshots/goldens always ineligible, or should repositories be able to select a lower-noise “reviewed snapshots remain eligible” preset? Jest explicitly treats snapshots as reviewable test artifacts despite generating them. ([Jest snapshot testing](https://jestjs.io/docs/snapshot-testing))
7. Should known generated schema dumps beyond Rails be added only after corpus validation, rather than guessing from generic names such as `schema.sql`?
8. Which monorepo package roots should delimit `build`/`dist` detection, if any, and can nearby tool configuration safely identify custom output directories without executing project code?
